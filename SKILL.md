# Grounded Roundtable

## Core contract

Create a thinking aid, not a fake historical exchange. The result combines separate videos into a virtual conversation whose claims can be checked against the original footage. Keep the virtual label visible on every slide and never imply that the participants heard or answered one another.

## Workflow

1. **Collect the input contract.** Require at least two YouTube URLs, speaker/video metadata, one topic (or propose the strongest common topic), a lens, a dialogue direction, and the intended audience. Use `same-domain` unless the user wants to connect different fields; then use `cross-domain`. Keep the lens separate from direction. Offer `tension-first`, `common-ground-first`, `forecast-to-choice`, and `solutions-first`; do not let the topic silently determine either input. Ask for one desired takeaway or propose a single sentence after comparing the sources; use it as the final message slide, not as a license to overstate the sources.
2. **Ingest once, then cache.** Retrieve metadata and captions/transcripts. Retry after the page/player finishes loading before declaring captions unavailable. If captions remain unavailable, request a transcript or produce an explicitly incomplete draft. Do not invent timestamps.
3. **Build the evidence map first.** For every participant claim store video ID, start/end seconds, timestamp URL, transcript span, source status, and a confidence note. Classify every anchor as `literal`, `metaphorical`, or `mixed`. A metaphorical or mixed anchor gets one semantic frame containing its source-image terms and underlying claim. Record every image-bearing content word: concrete nouns plus the surface fragments or irregular variants of image verbs and adjectives; do not stop after the nouns. Even for a short dialogue-only request, create a temporary manifest and validate each anchor before composing. Read [source contract](references/source-contract.md) for the fields.
4. **Establish relationships, then compose.** Before drafting a moderator question, connect the relevant semantic frames as `sequence`, `complement`, or `conflict`, name their shared decision dimension, and choose a compatible question mode. If the question is also stored in `claims`, link it with `semantic_connection_id` and keep the text identical. Then write 3–4 scenes with 6–10 turns each and 2–4 evidence anchors after a meaningful stretch of conversation. Participant turns are `direct quote`, `faithful paraphrase`, or `multi_anchor_synthesis`; each carries one atomic claim. For `cross-domain`, read [cross-domain bridges](references/cross-domain-bridges.md): an AI-labeled moderator bridge may appear only after both source positions are shown and must retain a consequential difference.
5. **Separate dialogue from evidence.** Dialogue uses `underlying_claim` and `shared_dimension`; it does not repeat linked source-image terms. Evidence and visuals may preserve verified source wording and imagery. Treat transcript translation as raw material, keep the source's strength and conditions, and rewrite into natural spoken Korean with clear subjects, ordinary connective endings, and short clauses. Read [dialogue rules](references/dialogue-rules.md) and [Korean naturalness pass](references/korean-naturalness.md).
6. **Render the deck.** Prefer native Google Slides when connected; otherwise produce a PPTX that imports cleanly. Use scene-centered conversation pages followed by evidence-anchor pages. If the user asks for a speaker-first flow, use `evidence-focus`: one concise speaker-claim slide followed by one full-size evidence slide with one native player. For native Slides, insert YouTube videos as `YOUTUBE` video elements using the original Video ID, set `videoProperties.start`/`end` to the evidence range, and set `autoPlay=false` unless the user requests autoplay. Retain a timestamp link beside the player as an external/open-in-YouTube fallback. Keep actual source players visually distinct from synthesized dialogue and include the short disclosure plus source notes. Use a read–modify–read transaction: update an existing player in place, or delete the exact fallback image before creating one; never create a second player in the same media slot. After the batch update, verify exactly one native player and zero images per evidence slide with `scripts/validate_native_structure.mjs` or an equivalent readback.
7. **Use a high-contrast visual system.** Default to a charcoal/navy canvas (`#0E1726` or similar), white body copy, and yellow (`#FFD34E`) for titles, key phrases, rules, and links. Never use yellow as a full-slide or large panel background. Keep titles large enough to scan at presentation distance (about 40–54 pt in a 16:9 deck), body copy concise (about 20–30 pt), and leave generous negative space. Do not add fake player frames, black overlays, or decorative play buttons when a native video element is present.
8. **Show provenance on the evidence slide.** Place a compact, readable source block beside the player with the YouTube channel name (linked to the channel), the original video link, speaker, Video ID, exact clip range, and caption/source status. Prefer the channel name and channel URL as the human-facing citation; keep the video URL as the direct evidence link. If channel/title metadata is not verified, write `제공된 원본 링크` rather than guessing. The visible source block and the `[Sources]` notes block must agree.
9. **Validate the exact final wording before rendering or delivery.** Put every final participant turn, moderator question, and bridge sentence into the manifest—not an earlier draft. Add `evidence_uses` when rendering a deck, then run `node scripts/validate_manifest.mjs <manifest.json>` even when the deliverable is dialogue only. It checks semantic-frame ownership, dialogue-layer image leakage, relationship/question compatibility, unsupported forced choices, anchor/clip reuse, and range/video mismatches. If it names a semantic violation, rewrite only that dialogue turn once, update the manifest with the rewritten text, and revalidate; if the second attempt still fails, stop and report the remaining diagnostics. Then check slide overflow, link preservation, native video IDs, source blocks, and the disclosure. If tokens or time are tight, reduce topic count, scenes, turns, and decoration in that order; never skip source verification.

Read the focused references only when routed above or needed for the output: [source contract](references/source-contract.md), [dialogue rules](references/dialogue-rules.md), [Korean naturalness pass](references/korean-naturalness.md), [Slides structure](references/slides-structure.md), [cost budget](references/cost-budget.md), and [cross-domain bridges](references/cross-domain-bridges.md) only for the `cross-domain` lens.

## Red flags

Stop and revise if a synthetic line is in quotation marks, says “you are right” or “your point,” assigns an AI bridge to a participant, states a cross-domain commonality without a visible difference, carries source-image terms into dialogue, invents a conflict between sequential or complementary claims, uses an unverified timestamp, treats automatic captions as final verbatim text, places a clip after every sentence, repeats an anchor/player without an explicit reuse reason, leaves a thumbnail under a native player, or hides the virtual disclosure in a single appendix slide.
